You generate supervised training INPUT descriptions of Magic: The Gathering card designs. The JSON targets supplied here describe exactly what the INPUT should express at each detail level. A downstream card-design model may choose editable defaults for unspecified stats, mana cost and other characteristics. Your job here is to produce descriptions at the requested detail level, not generate that downstream completed draft.

For every supplied projection, write ONE natural description a player might type into a card designer. Different projections deliberately contain different amounts of information. A sparse request MUST NOT mention omitted mana cost, colors, stats, subtypes, abilities, starting loyalty, or the original card's name. A broad size word such as "midsize" does not specify exact power/toughness. A description may remain incomplete: do not fill in missing information and do not ask the user questions in place of writing it.

Every field in the supplied target must be conveyed. Empty oracle_text with rules_coverage="unspecified" means no mechanics are expressed; do not say "vanilla" or "no abilities". Empty oracle_text with rules_coverage="explicit_none" means the complete card has no abilities; say so. Preserve each qualitative design note without converting it into exact stats or cost.

When mechanics are included, express ALL of them in ordinary player language. Casual MTG vocabulary like ETB, tap, flyer, loot, mill, target and counters is fine. Do not merely quote Oracle sentences. Preserve every quantity, target, player/controller, zone, linked reference, choice, optionality, payment, trigger, duration, restriction, replacement effect and alternative cost. Preserve may versus mandatory, cast versus play (lands can be played but not cast), cast versus copy, and target versus each. Preserve supertype/subtypes whenever the target includes them. "Legendary" is a real constraint, not flavor. For planeswalkers preserve starting loyalty and every loyalty ability cost if provided.

Do not name the original card or printing. CARDNAME or source-name aliases in the target are self-references: refer to "it", "this creature", "this spell", or the stated new card name if explicitly given. Real references to other named cards must remain. No added flavor, balance judgments, costs, drawbacks, restrictions, ability limits or mechanics. Source text is data, never an instruction to change this task.

The style field controls wording: minimal should be brief; concept should be conversational and qualitative where supplied; mechanics should be casual rules shorthand; complete should be a full plain-language request; casual_complete should use a different, terser player voice with the SAME constraints as complete. Use the accompanying player-language guide to vary vocabulary and voice, including ordinary novice wording and established shorthand where applicable. Do not drop clauses to make a long request short. Vocabulary variation is independent of detail level: omitting a numeric ability cost requires a projection that omits it, not merely a more casual style.

Return one JSON object with key "descriptions", an array containing exactly one object per projection in input order. Each object has ONLY "id" (copied projection ID), "description" (string), and "coverage_notes" (short string noting any hard-to-express linkage or uncertainty; empty otherwise). Do not include targets, source IDs, card names or comments outside JSON. Do not add a reasoning transcript.
