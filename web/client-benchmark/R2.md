# Model hosting on Cloudflare R2

**Production: https://cardforge.fyi/** (Cloudflare Pages project `cardforge`,
`cardforge-8am.pages.dev`). `www.cardforge.fyi` redirects in the browser before
the app loads, keeping card storage and model caches on the apex origin. Model assets
are served by R2 bucket `cardforge-models` at **https://models.cardforge.fyi**.
The tetrarcum.com and tetrarchs.com/forge/ deployments remain available for iteration.
The production site has no inference backend or permanently deployed Worker.

The launch uses 46 audited R2 objects (about 6.26 GB), including metadata and
licenses. The 93-file Pages upload is about 60 MB; its largest file is 16 MB.
The original five GGUF shards are preserved. A tensor exceeds the R2 REST
upload limit even when the splitter is asked for smaller shards, so the launch
copied these five objects through a temporary authenticated R2 import Worker,
verifying SHA-256 as R2 received each stream. That Worker and its secret were
deleted after import. Bonsai objects were uploaded through the REST API and
verified by byte length and ETag. No oversized original safetensors were uploaded.

The production [launch receipt](cardforge-launch-verification-20261010.json)
records uploads, deployment, browser checks, DNS and model caching.

Cloudflare's Free, Pro and Business CDN plans cache files up to
[512 MB](https://developers.cloudflare.com/cache/interaction-cloudflare-products/r2/).
This is a CDN cache limit, not R2's object-storage limit. Publication checks
require every object to be **strictly below 512,000,000 bytes**, avoiding ambiguity
between MB and MiB.

| Model | Published weight objects | Largest object |
| --- | --- | --- |
| Qwen3 Q4_0 | Five existing GGUF shards | 511,134,560 bytes |
| Bonsai text encoder | Nine binary transport chunks | 268,435,456 bytes (256 MiB) |
| Bonsai transformer | Six binary transport chunks | 268,435,456 bytes (256 MiB) |
| Bonsai VAE | One unchanged safetensors file | 168,120,878 bytes |

Existing Qwen shards already fit and retain their URLs/browser cache. Future
`prepare-model.py` runs request 480M shards and reject output at or above
the hard limit. `prepare-bonsai.py` also runs `chunk-model-assets.py`.
For weights already downloaded:

```bash
python3 chunk-model-assets.py dist/image-models/bonsai-ternary-2c24c81
python3 check-model-assets.py dist --hashes --output /tmp/r2-assets.json
node --test bonsai-chunks.test.mjs
```

Run the audit before publishing. Its JSON is the exact model upload list,
including model configuration, prompt, licenses and `transport.json`.
**Upload only the listed paths** relative to `dist`. Do not recursively upload
the original 2.26 GB and 1.43 GB safetensors files: they remain on the old host
for clients running an older release. Neither is requested by the updated
worker. Do not upload temporary `.part` files.

`transport.json` maps logical weight filenames to content-addressed chunks.
The worker passes a custom fetch function through the pinned Bonsai runtime's
existing `fetch` option. HEAD reports the logical size; each bounded Range
request becomes ranges on the corresponding small objects. Responses stream
in order, without allocating an entire multi-GB file. Invalid, truncated or
ignored ranges fail visibly. Tensor bytes, quantization, model identity and
IndexedDB tensor cache keys remain unchanged.

SHA-256 is verified against the upstream manifest during preparation. The audit
checks every output and recomputes each reconstructed source hash. This is a
publication check; browsers do not download whole chunks solely to hash
individual tensor-range reads.

## Repeat a Pages deployment

Start with the prepared `dist` tree, including the standalone renderer, parser,
model manifest and system prompt. The public repository does not contain weights.
The model preparation and renderer packaging steps are described in the benchmark
and Forge READMEs.

```bash
npm ci
npm run build
node cloudflare/build-pages.mjs
wrangler pages deploy pages-dist --project-name cardforge --branch main
```

`build-pages.mjs` places Forge at the root, keeps runtime code at `/model-bench/`,
rewrites only the production model URLs to R2, adds isolation/security headers
and early `www` normalization, and rejects objects above Pages' 25 MiB limit. It does
not mutate the iteration build or include model weights in Pages. Unknown paths
return a real 404. HTML and unversioned runtime configuration revalidate.

The tracked [CORS configuration](cloudflare/r2-cors.json) allows GET/HEAD/Range
from the production and Pages preview origins and exposes range/length/ETag
headers. The [cache rule](cloudflare/cache-rule.json) makes versioned GGUF,
safetensors and binary objects cacheable, respects immutable cache headers and
does not store error responses. Upload all objects **before** publishing a build
that references them. Avoid probing absent canonical URLs: upload verification
uses unique query strings so a cached 404 cannot masquerade as a failed upload.

```bash
python3 check-model-assets.py dist --hashes --output /tmp/cardforge-assets.json
wrangler r2 bucket cors set cardforge-models --file cloudflare/r2-cors.json --force
python3 cloudflare/upload-r2.py dist --audit /tmp/cardforge-assets.json \
  --account YOUR_ACCOUNT_ID --token-file /private/path/cloudflare.token \
  --only-prefix image-models/ --receipt /tmp/cardforge-image-upload.json
```

The uploader requires Python `requests` and an R2 write token. It accepts only
an audited list, verifies source hashes, streams uploads and skips objects only
when size and ETag match. Its conservative 300 MB limit matches the REST API;
use S3 multipart for larger objects. `cloudflare/import-worker.js` documents the
alternative used for this launch: a fixed allowlist of five existing public
shards, bearer authentication, bounded source URLs and R2 SHA-256 verification.
Deploy it only for an import, set `IMPORT_TOKEN` as a Worker secret, then delete
the Worker with `wrangler delete --config cloudflare/import-worker.jsonc --force`.
Never put credentials in a manifest or Pages assets.

On the current host, the zone-management token is stored in
`~/.config/cardforge/cloudflare-api.token` (0600, containing directory 0700).
It is separate from Wrangler's periodically synced account credential. DNS
management needs DNS Edit; the cache rule needs Cache Rules Edit; purging old
responses needs Cache Purge. Pages and R2 deployment use their own account scopes.

Validate after deployment:

```bash
CHROME_BIN=/path/to/chrome FORGE_URL=https://cardforge.fyi/ \
  node cloudflare/check-pages.mjs
CHROME_BIN=/path/to/chrome FORGE_URL=https://cardforge.fyi/ \
  node check-forge-demos.mjs
# Optional actual card-model download + CPU/Wasm inference smoke test:
CHROME_BIN=/path/to/chrome node cloudflare/check-text-model.mjs
```

The first check exercises the live renderer/parser, linked mtgish credit, browser
isolation, both pinned runtime imports and CORS byte ranges from all five GGUFs
and both chunked safetensors files. Check repeated ranges for `CF-Cache-Status:
HIT`; an HTTP 200 for a byte-range request is a failure for the Bonsai transport.
The launch separately compared small ranges from all 21 weight objects to local
bytes and verified CDN hits. Full Bonsai GPU generation remains a real-device
check; the server's software graphics tests are not a GPU performance benchmark.

Browser storage and caches belong to each origin. Model downloads and saved
creations from tetrarcum.com are not automatically shared with cardforge.fyi.
Users can export editable JSON with artwork from the existing site.

The 2026-10-10 checks verified all 46 publishable model assets and reconstructed
hashes. The pinned runtime's real safetensors reader recovered exact tensors
from both large files, including tensors crossing chunk boundaries, without a
request to either oversized source URL. These are transport checks, not a new
GPU inference benchmark.
